# Проверьте передачу сделки по той версии, которую приняли

**CRM RevOps Kit** сопоставляет локальный пакет передачи сделки, подтверждение
его приёма и предоставленный снимок CRM. В отчёт попадут изменённый пакет,
отсутствующий или отклонённый приём, другой ответственный или этап, просроченный
следующий шаг и данные, по которым нельзя установить состояние на выбранный
момент.

Результат — очередь ручной проверки одного процесса передачи. Статус
`consistent` означает, что предоставленные поля согласованы. Хеш не доказывает,
что человек прочитал пакет, что источник достоверен или что клиент согласовал
следующий шаг.

Python 3.9+, только стандартная библиотека. Работа локальная, без модели,
аккаунта, API-ключа и покупки ядра. На входе нужен JSON по явному контракту
модуля. Программа не загружает произвольные форматы экспорта CRM, не открывает
ссылки на источники, не пишет людям и не меняет CRM.

## Повторите учебный пример

Распакуйте архив выпуска v0.1.0 в новую папку. Выполните из неё:

```bash
python3 -B crm_revops_kit.py --json doctor
python3 -B crm_revops_kit.py --json fingerprint examples/synthetic-handoffs.json
python3 -B crm_revops_kit.py --json audit examples/synthetic-handoffs.json
```

В наборе шесть вымышленных передач. Момент проверки задан явно:
`2026-11-10T09:00:00+03:00`; текущее время компьютера не подставляется. Одна
строка согласована, пять требуют проверки:

| Ситуация | Что должен показать отчёт |
|---|---|
| Пакет, подтверждение и пригодный снимок совпадают | `consistent` |
| Подтверждения нет | `ACK_MISSING` |
| После подтверждения пакет изменили | `ACK_HASH_MISMATCH` |
| В снимке указан другой ответственный | `OWNER_MISMATCH` |
| Срок следующего шага уже прошёл | `NEXT_STEP_OVERDUE` |
| Получатель отклонил пакет | `ACK_REJECTED` |

[Входной файл](examples/synthetic-handoffs.json) · [Полученный отчёт](examples/synthetic-report.json).
Это учебные данные, а не клиентский кейс, замер ответа модели или результат
продаж Lookatshow.

`audit` и `demo` возвращают **код завершения 1**, если корректный отчёт содержит
строки для проверки. Для этого примера так и должно быть. Код 0 означает, что
все предоставленные строки согласованы; код 2 — ошибку данных или выполнения.
Читайте код вместе с JSON. Не скрывайте любой исход через `|| true`.

## Установите команду

В POSIX-системе выберите новую папку установки и папку команд:

```bash
python3 -B install.py --prefix "$HOME/.local/share/crm-revops-kit" --bin-dir "$HOME/.local/bin"
export PATH="$HOME/.local/bin:$PATH"
cd /tmp
crm-revops-kit --json doctor
crm-revops-kit --json demo
```

Установщик создаст отдельную копию нужных файлов и команду с тем интерпретатором
Python, которым его запустили. Занятые пути установки и команды сохраняются;
при конфликте выберите другие. Не удаляйте этот интерпретатор. Собственные
входные данные и отчёты храните вне папки установки.

Нативный установщик рассчитан на POSIX. В Windows запускайте исходник:
`python crm_revops_kit.py ...`, подставив имя своей команды Python вместо
`python3`. Наличие файла CI само по себе не подтверждает запуск на другой ОС.

Необязательная команда `crm-revops-kit --json onboard` один раз покажет ссылки
автора и создаст локальную отметку `.onboarded`. В обычном JSON и сохранённых
отчётах рекламных вставок и телеметрии нет.

Для удаления используйте те же два пути из любой рабочей папки:

```bash
python3 -B "$HOME/.local/share/crm-revops-kit/uninstall.py" --prefix "$HOME/.local/share/crm-revops-kit" --bin-dir "$HOME/.local/bin"
```

Удаление проверяет хеши принадлежащих модулю файлов и сохраняет остальные
пользовательские файлы. Если установка изменена или неполна, сначала выясните,
что произошло, и только затем повторяйте удаление.

## Проверьте свою передачу

Прочитайте [контракт входных данных](docs/INPUT-CONTRACT.md) и
[порядок передачи](docs/HANDOFF-WORKFLOW.md). Подготовьте разрешённый локальный
JSON вне папки установки. Явно задайте момент наблюдения и выбранный предел
возраста снимка. Сохраните реальные источники, по которым человек сможет
проверить содержание.

```bash
crm-revops-kit --json schema
crm-revops-kit --json fingerprint ./handoffs.json
crm-revops-kit --json audit ./handoffs.json --output ./handoff-review.json
```

`fingerprint` выдаёт канонический JSON каждого пакета и его SHA-256. После
проверки по принятому в команде процессу получатель может зафиксировать приём
или отказ именно от этой версии в `acknowledgements`. Любая правка поля пакета
меняет его хеш. Программа не создаёт подтверждение за человека и не
удостоверяет его личность.

Файл отчёта содержит тот же JSON, что и stdout. Существующий файл сохраняется,
пока вы явно не выбрали `--replace`. Совпадение пути или жёсткой ссылки входа и
выхода запрещено. Выбирайте реальные пути без родительских папок-символических
ссылок: такой путь выхода отклоняется. При некорректном входе файл отчёта
не создаётся.

Полноту `snapshot.complete` указывает тот, кто готовит данные. Неполный,
просроченный, будущий или слишком ранний снимок не устанавливает ответственного
и этап после передачи. Отсутствующая сделка требует проверки и не доказывает,
что записи нет в CRM. Время сравнивается в UTC с учётом явных смещений. Будущее
подтверждение нельзя использовать при проверке более раннего момента.

## Готовый запрос агенту

> Проверь этот разрешённый локальный JSON через CRM RevOps Kit. Запусти doctor,
> затем fingerprint и audit. Сохрани код завершения: 1 означает корректный отчёт
> со строками для проверки. Покажи каждую причину и ID передачи. Объясни, что
> предоставленные источники устанавливают на as_of и что остаётся неизвестным.
> Не делай выводов о согласии клиента, личности получателя, достоверности
> источника, оплате или фактической доставке в CRM. Не меняй пакет, не создавай
> подтверждений, не пиши людям и не меняй CRM. Верни путь отчёта и один нужный
> ручной шаг для каждой незакрытой передачи.

[Навык в комплекте](skills/crm-revops-kit/SKILL.md) задаёт такой же порядок для
агента, умеющего запускать локальные Python-команды. Это не MCP-сервер и не
сертификат совместимости со всеми агентами.

[Bitrix Read Kit](https://github.com/ilookatshow-gif/bitrix-read-kit) решает
соседнюю задачу: читает видимые CRM-дела с явными границами выборки. CRM RevOps
Kit сверяет предоставленную передачу. Видимое дело или совпавшее подтверждение
не устанавливают весь жизненный цикл клиента.
